### Strict evidence details

Runner: disposable Ubuntu 26.04 cloud-image VM under QEMU/TCG, booted from the
dated image with sha256 `7b90593f5532b49b7e3fe3d2743f0d1f0d822e5b07cebcd8e00c0df8069ecab9`
(the same pinned image recorded by the rc.1/rc.2 evidence). The lane ran as
user `marqdo` (uid 1000, `root: false`) with bubblewrap 0.11.1: the seven
adversarial isolation tests, the strict CLI contract, strict resource refusal,
inert `@knowledge` and the forged-marker rejection all passed
(`G-C security lane: PASS`). The evidence records `tested_sha_verified: true`
(from `git rev-parse`), the kernel (`7.0.0-43-generic`), cgroup v2 and the
toolchain used by the lane (`rustc 1.100.0`). The published archive was then
unpacked inside the same guest, its checksum and `SOURCE_SHA` verified,
`inspect --platform` reported strict `available`, and strict
`run examples/hello.mq.md` plus
`call examples/factorial.mq.md 数学.阶乘 --arg n=5` produced the expected
output.

### G4 performance and the shared-node exception

Three paired runs compare `v3.0.0-beta.1` with this candidate on Woodpecker
agent 1 (shared node: Intel i7-12700H, kernel 7.0.0-31-generic, `powersave`
governor, logical CPU 0 pinned, five warmups and twenty samples per workload,
nine workloads). Every workload is correctness-verified in every run.

| Paired run | p50 delta range | Threshold breaches (>= +15% p50) |
|---|---|---|
| [#81](https://ci.cflmy.cn/repos/1/pipeline/81) | -28.45% … +1.52% | none |
| [#82](https://ci.cflmy.cn/repos/1/pipeline/82) | -28.02% … +4.10% | none |
| [#83](https://ci.cflmy.cn/repos/1/pipeline/83) | -23.00% … +1.23% | none |

The timed command is now the plain execution path while correctness is verified
against the current Observation snapshot, so an opt-in observability document
is not billed as a regression. The first candidate build compared
`--output json` against the beta summary and produced a spurious
+240%…+375% p50 delta; that comparison was rejected and the sampler fixed
before the frozen SHA.

RSS deltas computed across the two *different* sampler versions are an artefact
of `ru_maxrss` inheriting the sampler parent's pages; the baseline report is
produced by the beta-tagged sampler. A same-parent `/usr/bin/time` cross-check
of the archived binaries (rc.3 vs rc.2, eight comparable workloads) shows RSS
deltas between -4.69% and +13.27%, below the +20% threshold
(`rss-investigation.json`; `stdlib-print-demo` is excluded because the rc.2
checkout does not load the candidate stdlib in that layout).

**Maintainer approval:** the shared-node G4 `WARN` is approved for
`v3.0.0-rc.3` only (2026-11-24). Shared-node reports stay `SMOKE`; they are
never promoted to a dedicated-node claim, and a fixed node is planned for the
next cycle.

## Behaviour changes since rc.2 (review closure)

A code review of the first candidate build found and closed: a strict run
emitting a partial JSONL stream for a destination it refuses; a stale Analysis
artifact surviving a load failure; `fs.*` effects collapsing to
`resource.request`; plugin frame error codes flattened; event/snapshot `level`
enums disagreeing; snapshots embedding absolute host paths; option errors
using the wrong phase; and a G4 workload catalogue that still passed the
retired `--json` flag. Each has a regression test and is recorded in
[STATUS.md](../STATUS.md) section 0.9.1.

## What this evidence does not claim

Stable `3.0.0`, LTS, Windows/macOS support, strict L2, dedicated-node
performance, or a publisher signature. Checksums are integrity only.
