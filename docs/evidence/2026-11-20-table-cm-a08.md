## Layers

* GFM source: unchanged parser/AST/laziness.
* Logical value: `Value::Table` keeps ordered headers/rows, width validation,
  equality/display/wire and copy (no aliasing).
* Physical storage: T0 `Vec<Vec<Value>>`, unchanged and private to the
  implementation; T1/T2/T3 are explicitly not done.

## Stdlib module

`stdlib/data/table.mq.md` (import `std:data/table`):

```text
选择列(数据, 列)
过滤数值大于(数据, 列, 阈值)
排序(数据, 列) / 插入有序(...)
追加行(数据, 行)
设置单元格(数据, 目标行, 目标列, 值)
连接(左, 右, 左列, 右列)
分组(数据, 键列, 值列)
```

All are `.mq.md` functions using `table.columns/row/cell`, `list.*`, `map.*`
and `表`. Every result is a new value; inputs are never mutated.

## Self-test

`stdlib/tests/table.mq.md`:

```text
data = [名称,分数]: 甲87, 乙92, 丙71
选择列(1)      -> header [分数]
过滤 >80       -> 甲87, 乙92
排序(1)        -> 丙71, 甲87, 乙92
追加行(丁65)   -> 4 rows
设置单元格(0,1,99) -> 甲99
连接(左,右,0,0) -> 2 matched rows, 4 columns
分组(类别,值)   -> {a:[1,3], b:[2]}
original data  -> unchanged
```

`crates/cli/tests/stdlib_table.rs` runs it through the CLI with
`MARQDO_STDLIB_DIR` and asserts every shape/order plus input immutability.

## Not done

* No T1 controlled storage interface, T2 column store, T3 views, or
  Memory-backed numeric columns.
* No `DataFrame`/`TableView` value types; no mutable table operations.
* No generic mixed-type sort/group beyond the explicit numeric/Text contracts.
* No change to GFM parsing, rendering, spans or references.
* No external stdlib repository publication and no Windows/macOS evidence.
