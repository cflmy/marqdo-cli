## Case-level observations

| Attack/surface | Observed inside sandbox |
|---|---|
| identity | `uid=1000`, `pid=1`, `NoNewPrivs: 1`, `CapEff: 0` |
| `/etc/shadow`, `/root`, `$HOME` | `DENIED` |
| `/project/allowed.txt` | `OK` |
| write outside project / into `/project` | `DENIED`; no host file created |
| write `/tmp` | allowed in private tmpfs, host unaffected |
| `/proc/1/root/etc/shadow` | `DENIED` |
| inherited fds above stdio | none |
| `setuid(0)`, `mount`, nested `unshare` | `DENIED` |
| IPv4 connect / raw socket | `DENIED` |
| fd loop | `EMFILE` <= 64 |
| fork loop | bounded below 200 |
| 768 MiB touch | denied/killed by 512 MiB `RLIMIT_AS` |
| infinite CPU loop | stopped by wall-clock/CPU budget |
| 4 MiB stdout | stopped at the 64 KiB output limit |

## Residual risks and non-claims

* Strict L2 (Worker/Foreign inherit the sandbox) is not implemented; those
  flags are rejected. Native ABI is never allowed in strict.
* rlimits are used instead of cgroup-v2 accounting; no cgroup enforcement is
  claimed.
* Filesystem TOCTOU is reduced by read-only mounts but not formally proven
  against a racing host user.
* Network is denied by the network namespace, not a seccomp syscall allowlist.
* A remote self-hosted security-lane CI run is still required for a CI-signed
  G-C. `.github/workflows/security-linux.yml` defines that lane and must not be
  replaced by GitHub-hosted runner success.
